# Quant Backend Phase 0 / Phase 1

## Scope
- Progressive backend migration without rewriting the app.
- Preserve Electron compatibility while moving backend concerns into `backend/`.
- Prepare for VPS Ubuntu/Linux, PM2, systemd, Docker, and future SaaS evolution.

## Phase 0 delivered
- `REAL_TRADING` default disabled in `.env.example` and runtime state starts safe.
- Authoritative backend state persisted in `quant_data/backend_state.json`.
- Risk baseline persisted in `quant_data/risk_config.json`.
- Global kill switch introduced at backend state level.
- Real trading now requires:
  - `.env` arming via `REAL_TRADING=true`
  - backend state `tradingRealEnabled=true`
  - valid minimum risk rules
  - kill switch inactive
- Training and real trading are independent backend toggles.
- MT5 kept optional; Binance remains primary.
- Health check route prepared at `/healthz`.

## Phase 1 delivered
- New backend modules:
  - `backend/config`
  - `backend/logging`
  - `backend/memory`
  - `backend/risk`
  - `backend/routes`
  - `backend/server`

- New REST endpoints added:

  - `POST /api/bot/trading-real/on`
  - `POST /api/bot/trading-real/off`

  - `POST /api/bot/training/off`
  - `GET /api/trades`
  - `GET /api/signals`

  - `POST /api/connections/mt5/test`
- Structured JSON logging introduced for backend lifecycle and state changes.
- Retry-with-backoff utility introduced for adapter checks.

## Google OAuth preparation
- Future auth implementation should touch:
  - `backend/auth/` for OAuth strategy and token/session exchange
  - `main.js` or a future `backend/server/http-server.js` for callback routes
  - user persistence store to add:
    - `provider`
    - `providerUserId`
    - `avatarUrl`
    - `lastLoginAt`
- Private API endpoints should ultimately rely on role-aware backend auth middleware rather than renderer state.

## Multiuser preparation
- Current user config store is file-based and transitional.
- SaaS migration target should move user/config/state persistence to a real DB with ownership boundaries:
  - users
  - exchange_connections
  - bot_states
  - risk_profiles
  - trades
  - signals
  - training_logs
